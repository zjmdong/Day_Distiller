# SMTP 邮件配置教程

## 获取参数

从邮箱服务商后台确认 SMTP 主机、端口、安全方式、发件地址、用户名和应用密码。常见组合是 465 + SSL/TLS，或 587 + STARTTLS；以服务商文档为准。开启双因素认证的邮箱通常必须创建“应用密码”，不能直接使用网页登录密码。

## 应用内填写

1. “SMTP 主机”：例如服务商提供的 `smtp.example.com`。
2. “SMTP 端口”：与安全方式匹配。
3. “SMTP 安全”：生产环境选择 SSL/TLS 或 STARTTLS；“无加密”仅适合本机测试夹具。
4. “SMTP 用户名”：通常是完整邮箱地址。
5. “SMTP 应用密码”：只在应用内填写并保存到系统安全凭据库。
6. “发件地址”与“收件地址”：部分服务商要求发件地址必须与登录用户一致。

SMTP 成功的定义是服务器接受 `send_message`。这不保证最终进入收件箱；仍需查看退信、垃圾邮件和服务商日志。应用为首次自动发送使用任务级确定性 Message-ID，崩溃恢复时若数据库已有成功回执就跳过发送。手动再次发送使用“任务 + 报告内容摘要”的稳定 Message-ID。

## 本地测试

在没有真实邮箱时选择 Mock 模式，应用会把完整 MIME 邮件写到 `%LOCALAPPDATA%\DayDistillerV2\mock_outbox`。可用邮件客户端打开 `.eml`，检查主题标题、暖心话、CID内嵌海报，以及独立的原图和PDF附件。

## 常见错误

- 认证失败：用户名、应用密码或 SMTP 权限错误。
- 连接超时：主机/端口、防火墙或代理问题。
- TLS 错误：端口和安全方式不匹配，或系统证书异常。
- 550/553 拒绝：发件地址不允许、收件人无效或服务商策略拒绝。
- 正文图片不显示：邮件客户端可能禁用内嵌资源；应用同时附带原始海报文件，可从附件直接打开。若所有客户端均不显示，检查邮件源码中海报的 `Content-ID` 是否与HTML中的 `cid:`一致。

服务器拒绝或连接失败时任务进入 `failed`，设备记录不会被删除。修正设置后在报告历史点击“重试失败任务”。
